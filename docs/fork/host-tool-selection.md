# Host tool selection

This fork resolves configured-agent and runtime-registered agent tool selections during effective discovery, after native settings are applied. Set a global `subagents.toolSelectionResolver` file path in the Pi agent settings. Home-relative paths expand at the filesystem boundary and relative paths resolve against the agent directory. Project settings cannot choose executable provider code, including in project-only agent scope.

The provider exports synchronous `resolveTools({cwd, agentDir, scope, projectTrusted, selections})`. Each selection contains `agentName` and `selectors`. It returns an ordered array with identical cardinality: `{ok:true, selectors:string[]}` or `{ok:false, error:string}`. The public contract types and existing effective `discoverAgents` reader are exported through `pi-subagents/agents`.

Only the loaded callable is cached by canonical path. Providers must re-read configuration for each batch. Jiti uses `fsCache:false`, `moduleCache:false` and `tryNative:false`; the published Pi SDK is loaded natively to avoid SDK retranspilation. Undefined and empty selections retain their native semantics without calling the provider.

Errors become agent discovery diagnostics carrying canonical, local and alias identities. Affected effective agents are omitted, preventing fresh launches. Raw declaration views remain unchanged. Existing recovery descriptors still supply persisted tools when the current agent cannot be resolved. Invalid global resolver settings are diagnosed even in project-only scope because the executable provider is a global setting.

Runtime agents registered through `registerAgent()` or the registration event may declare tool-group aliases in `definition.tools`. The owner resolves those selectors using the current discovery directory, scope and trust state. The registration stays raw, so later discoveries pick up group configuration changes without re-registering the agent. Runtime agents retain the official ownership contract: only model-tier settings override their definitions; `agentOverrides.<name>.tools` remains ignored. Resolution failures appear in discovery diagnostics and management list/model queries. Registration itself has no discovery context and does not resolve selectors. The public `discoverAgents()` reader and preflight API still describe configured agents, not a process-local runtime registry.

Diagnostic matching preserves native canonical, local and alias precedence before source priority, so a rejected alias cannot block a different valid canonical agent. Provider batches and selector arrays must be dense. Validation uses the original batch cardinality even if provider code mutates its request, and malformed outputs produce diagnostics rather than retaining raw permissions or rejecting public preflight with an exception.

The host is responsible for group policy. This fork does not import private harness modules, scan a second agent tree or generate settings overrides. Native launch planning, availability, ceilings, MCP authorization and resume retain their owners.
